# Python bindings for NSH — research brief (2026-11-03)

Compiled from 4 scouts (2× Grok 4.6, 2× Haiku). ✅ = re-checked directly.

## Verdict: Path B (bind NSH's public Rust app API), out of tree, no fork

- **Path A (Python as a sibling of `nsh-js`) is not possible without forking.** `nsh_core::js::host` is a public *JS prop decoder*, not a host plugin API. `nsh-engine` hard-wires QuickJS: `App::{Rust(Root), Js(Bundle)}`, a private `Script` type and the `js` feature. There is no `register_host`.
- **Path B works on crates.io 0.3.0.** It's the same path `examples/gallery-rs` and `nsh init --template rust` use:
  - ✅ `nsh_platform_linux::{run_app, AppSource, AppOptions, AppView, Root, set_ui_sets}` are public.
  - `run_app(AppSource::Rust(Root::of::<App>()), AppOptions{..})` runs on the process main thread.
  - The macOS and Windows platform crates expose the same names, but only compile on their own OS.
  - Use `default-features = false` to drop QuickJS.
- **Dynamic trees:** `view()`, `text()`, `.child()`, `.children()`, ✅ `dynamic(f)`, `when`, `each` and `AnyElement` can all be built at runtime, with no macros.
- **Handlers:** `on_press(impl Fn() + 'static)` is stored as `Rc<dyn Fn>`. It is **not `Send`**, so it can capture `Py<PyAny>`.
- **Root props factory:** `Root::new(props: Fn() -> P + Send + Sync + 'static)`. It crosses from the main thread to the engine thread, and `Py<PyAny>` is `Send + Sync`, so that's fine.
- **Tailwind strings:** ✅ `.app_class(impl IntoReactive<Option<SharedString>>)` exists in `element/builder.rs`. The core parses class strings natively and caches them, so Python can offer `class_="p-4 gap-2"`. We need to confirm it's callable on every element.

## Threading model for nsh-py

```
Python main thread ── ui.run(App) ──► Rust: release the GIL → platform::run_app (GTK/AppKit/Win32 loop)
                                         │  a timer re-attaches periodically → Python::check_signals (Ctrl-C)
engine thread "nsh-engine" ──► Component::view / on_press / dynamic closures
                                         └─ Python::attach → call Py<PyAny>
```
- The reactive graph panics if it's used off the engine thread. All Python UI code must run there.
- `check_signals` does nothing off the main thread, so Ctrl-C has to be handled by a timer on the UI loop.
- PyO3 0.30.1: `attach`/`detach` (formerly `with_gil`/`allow_threads`). Free-threaded builds would need separate wheels; we defer that.

## Public Rust API surface (to mirror in Python)
- **Primitives:** view, text, image, scroll, `virtual_list(count, |at| row)`, canvas, shader, input, overlay, web_view, video, `when`/`each`/`dynamic`/`catch_error`.
- **nsh-base:** button, checkbox, switch, radio(_group), toggle(_group), select, combobox, slider, number_input, otp_input, progress, link, avatar(_group), accordion*, calendar, date_picker, time_field, collapsible, carousel, pagination, tabs, dialog, alert_dialog, sheet, popover, hover_card, tooltip, menu, toast(_stack), nav_stack/nav_page, dock_area, resizable panels, text_view, editor, diff_view, table, data_table, tree, command, toolbar, scrollbar, color_*, plot (line, area, bar, pie, arc).
- **Reactivity:** `signal`, `signal_with(SignalEquals)`, `computed` (Memo), `effect`, `cleanup`, `batch`, `untracked`, `provide_context`/`use_context`, `create_root`. Signal: `get`, `with`, `get_untracked`, `set`, `update`, `read_only`.
- **Events:** `on_press()`, `on_change(&str)`, `on_focus`/`on_blur`, `on_submit(&str)`, `on_key_press(&str)`, `on_scroll(&ScrollEvent)`; on lists, `on_viewable_items_change` and `on_load_more`.
- **Theme:** shadcn `cssVars` JSON, `Theme::from_json`, `AdaptiveColor` for light and dark, appearance light/dark/system.
- **Testing:** `Headless::start(EngineConfig::new(Root::of::<App>()))`, `.press("text:Add")`, `.type_text("id:x", ..)`, `.wait_for(..)`. No display or GPU needed, works on all 3 OS.

## Platforms and build

| OS | Backend | Build needs | Runtime minimum |
|---|---|---|---|
| macOS | AppKit | Xcode CLT, stable Rust (edition 2024) | macOS 14+ |
| Windows | Win32 + Direct2D | VS Build Tools (C++), Windows SDK, **LLVM/libclang** | Win 10 1809+, WebView2 for web views |
| Linux | GTK 4 | clang, libclang-dev, `libgtk-4-dev` (+ `libwebkitgtk-6.0-dev` optional) | **GTK 4.14+, glibc 2.39** (NSH builds on Ubuntu 24.04) |

- **Linux distros that work:** Ubuntu 24.04+, Debian 13, Fedora 40+, Arch.
- **Linux distros that don't:** Ubuntu 22.04 (GTK 4.6) and Debian 12 (GTK 4.8). Tell sprinters this in advance.
- The GPUI backend (gpui-fast 0.1.9) runs on Linux without GTK 4.14, but needs Vulkan and GTK 3. It's meant for embedding, not packaging.

## Linux wheels — key constraint
- GTK 4 isn't on the manylinux whitelist, and NSH itself doesn't ship manylinux builds.
- Precedents: PyGObject ships sdist only and uses the system GTK. wxPython ships per-distro `linux_x86_64` wheels.
- **Plan:**
  - macOS and Windows: normal abi3 wheels on PyPI.
  - Linux: build on Ubuntu 24.04, require system GTK 4.14+, and give a clear `doctor` error. Investigate whether a `manylinux_2_39` tag with an external GTK requirement is acceptable on PyPI. Otherwise publish the Linux wheels as GitHub release or extra-index wheels, which is what gpyui and wxPython do.
- To verify on day one: does the PyO3 cdylib link GTK through DT_NEEDED, and what does `auditwheel show` report?

## Prior art
- No Python bindings for NSH exist (GitHub, PyPI and the NSH tracker were searched). Little coverage so far: two HN posts at 2 points each.
- Python reactivity APIs to copy: **reaktiv** (`s()`, `.set`, `.update`, `@computed`, `effect`), which is the closest to Solid. None of the Python libraries detect in-place list or dict mutation, so we either provide reactive collections or document the rule.

## Day-1 PoC (smallest)
1. A maturin cdylib with `nsh-core`, `nsh-base` and `nsh-platform-linux`, all `=0.3.0`, with `default-features=false`.
2. A Rust `#[component] fn PyRoot()` that calls a stored Python factory through `Python::attach` and converts the returned tree (view/text/button + `class_` + `on_press`) using `dynamic`.
3. `ui.run(App)`: release the GIL, then call `run_app`. Add a main-thread timer for Ctrl-C.
4. The counter example with a Python `signal` backed by an NSH `Signal<PyObj>`, or a Python-side signal that triggers `dynamic` re-runs. This is the main design decision to make in the spike.
5. A headless test through `nsh-testing`.
6. CI matrix: Linux (ubuntu-24.04), macOS, Windows.
